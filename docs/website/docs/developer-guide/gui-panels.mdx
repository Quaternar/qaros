# Custom GUI Panels

<LanguageSwitcher />

GUI panels let you place your application's 2D interfaces into the shared 3D room: dashboards, settings pages, control surfaces. Panels are *shared session state* — every peer sees the same panel at the same place, live. A panel shows either **web content** — the panel renders a URI, which makes any existing web UI immediately usable in the room — or a **video stream** from a video sender. Chain `QarGuiPanelUrlExt` or `QarGuiPanelStreamIdExt` into `QarGuiPanelInit` to choose (C#: `GuiPanelOptions.ContentUri` or `ContentStreamId`); the content type is fixed at creation. The examples on this page use web content.

The concepts (identity by common name, top-edge-midpoint pose, size + content scale, per-peer visibility) are explained in [The QAROS World](/docs/user-guide/qaros-world#gui-panels) and [Coordinate Systems](/docs/developer-guide/coordinate-systems#gui-panels--2d-quads-in-room-space).

## Creating a panel (idempotent)

Panels are identified by a stable **common name**; `get_or_create` returns the existing panel or creates it — safe to call on every app start:

<CodeTabs>
<Lang value="c">

```c
QarGuiPanelInit init = qar_gui_panel_init_default();
init.common_name = "machine-status.myapp.example.com"; /* stable identity */
init.display_name = "Machine Status";

init.pose = qar_pose_default();
init.pose.position.y = 1.5f;      /* top-edge midpoint, room space, meters */
init.pose.position.z = -1.0f;

QarGuiPanelSize size = qar_gui_panel_size_default();
size.width_meters = 0.8f;
size.height_meters = 0.5f;
init.size = size;

QarGuiPanelId panel_id;
QarResult r = qar_gui_panels_get_or_create(session, &init, &panel_id);
qar_result_log_if_error(r);

qar_gui_panels_navigate_to_uri(
    session, &panel_id, "https://myapp.local/status-dashboard");
```

</Lang>
<Lang value="csharp">

```csharp
using Quaternar.Qaros.Mathematics;

var options = new GuiPanelOptions("machine-status.myapp.example.com") // required, stable identity
{
    DisplayName = "Machine Status",
    // Pose is the top-edge midpoint, room space, meters.
    Pose = new Pose(Quaternion.Identity, new Vector3(0f, 1.5f, -1.0f)),
    Size = new GuiPanelSize(0.8f, 0.5f, 1.0f),   // width, height, content scale
};

// get_or_create: returns the existing panel or creates it. Idempotent.
Result<GuiPanelId> created = session.GuiPanels.GetOrCreate(options);
GuiPanelId panelId = created.ValueOrThrow();

session.GuiPanels.NavigateToUri(panelId, "https://myapp.local/status-dashboard")
    .EnsureSuccess();
```

:::tip Choosing common names
Use a DNS-style, application-scoped name (`<panel>.<app>.<org>`) and keep it constant across versions. The panel's ID is derived deterministically from it — restarting your app reattaches to the same panel instead of spawning duplicates.
:::

## Manipulating panels

All mutations go through the session and the panel ID:

<CodeTabs>
<Lang value="c">

```c
qar_gui_panels_update_pose(session, &panel_id, &new_pose);      /* move it   */
qar_gui_panels_change_size(session, &panel_id, &new_size);      /* resize    */
qar_gui_panels_set_state(session, &panel_id, QAR_GUI_PANEL_STATE_MINIMIZED);
qar_gui_panels_navigate_to_uri(session, &panel_id, "https://...");
qar_gui_panels_close_panel(session, &panel_id);                 /* remove    */
```

</Lang>
<Lang value="rust">

{/* Generated by cargo xtask guide from examples/guide/gui-panels.md of the Rust binding. Edit that file, not this tab. */}

```rust
let panels = session.gui_panels();

panels.close(panel_id)?; // remove
```

</Lang>

Panel states: `VISIBLE`, `MINIMIZED`, `HIDDEN`, `CLOSED`.

### Per-peer visibility

By default a panel is visible to everyone: an **empty** visibility set means every peer, never none. Removing the last peer therefore shows the panel to everyone again; to hide it, set its state. A panel meant only for some peers is best created with them in `QarGuiPanelInit::visible_to_peers`. An existing one is narrowed by editing the set — for example an operator-only control panel:

<CodeTabs>
<Lang value="c">

```c
const QarPeerId* add[] = { &operator_peer_id };
qar_gui_panels_update_visible_to(
    session, &panel_id,
    add, 1,      /* additions */
    NULL, 0);    /* removals  */
```

</Lang>
<Lang value="rust">

{/* Generated by cargo xtask guide from examples/guide/gui-panels.md of the Rust binding. Edit that file, not this tab. */}

Editing the visibility set is raw only: call `qar_gui_panels_update_visible_to` through `library.raw_api()` with the session's `as_raw()`.

```rust
// Editing the visibility set is raw only: call the raw table with the session's handle.
let api = library.raw_api();
let panel = QarGuiPanelId { data: panel_id.0 };
let operator_peer_id = QarPeerId { data: operator.0 };
let mut additions = [&raw const operator_peer_id];
// SAFETY: the session is alive and used on this thread; the ids outlive the call.
let result = unsafe {
    (api.qar_impl_gui_panels_update_visible_to)(
        session.as_raw(),
        &raw const panel,
        additions.as_mut_ptr(),
        additions.len(),
        std::ptr::null_mut(), // no removals
        0,
    )
};
// SAFETY: plain value argument.
unsafe { (api.qar_impl_result_log_if_error)(result) };
```

</Lang>
</CodeTabs>

## Observing panels

Your app can react to panels changing — whether changed by another peer, another app, or a user grabbing the panel in the room:

- `qar_gui_panels_subscribe_updates(session, callback, state, token)` — all panels,
- `qar_gui_panels_subscribe_panel_updates(session, &panel_id, callback, state, token)` — one panel,
- `qar_query_gui_panels_count` / `qar_query_gui_panels` — enumerate current panels (count-then-fetch),
- per-panel getters: `qar_gui_panel_get_display_name`, `_get_pose`, `_get_size`, `_get_state`, `_get_content_uri`, `_get_visible_to_peers`.

Update callbacks arrive on library threads — see the [callback rules](/docs/developer-guide/api-conventions#4-blocking--async-pairs).

In Rust, `session.gui_panels()` lists the panels (`list`) and subscribes to all of them or to one (`subscribe`, `subscribe_panel`), with owned snapshots: [GUI Panels](/docs/developer-guide/tutorials/rust/gui-panels).

## Integration patterns

**Expose your app's existing web UI.** If your application already serves a web frontend (local status page, embedded HTTP server), a panel is a one-call integration: `get_or_create` + `navigate_to_uri` pointing at your server. Interaction happens directly in the room.

**Drive app state from a panel.** Host a small web page that calls back into your application (REST/WebSocket). The panel is shared, so any user in the room can press the buttons; your app sees the effect and updates its rendered content accordingly.

**Attach a panel to your app volume.** Panels don't parent to volumes automatically, but you can keep one docked: subscribe to your volume's pose updates and reposition the panel relative to it. Remember the differing conventions — panel pose is the **midpoint of its top edge**, volume pose is the **center**.

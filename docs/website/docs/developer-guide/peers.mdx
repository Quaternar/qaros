# Working with Peers

<LanguageSwitcher />

Every participant in the session — devices and applications alike — is a **peer**. The peer API lets your application answer "who is here?", present itself well, and react to arrivals and departures. (Concept: [The QAROS World](/docs/user-guide/qaros-world#devices-in-the-shared-space).)

:::info
The C# snippets on this page are illustrative — they track the `Quaternar.Qaros` binding
surface but are not yet compiled from a published sample project.
:::

## Presenting your application

Your own peer's metadata is set at onboarding time via `QarPeerPresentation` (display name, app version, custom info string) and can be updated live:

<CodeTabs>
<Lang value="c">

```c
qar_peer_update_display_name(session, "My CAD Tool — Assembly B");
```

</Lang>
<Lang value="csharp">

```csharp
session.Peers.UpdateDisplayName("My CAD Tool — Assembly B").EnsureSuccess();
```

</Lang>
<Lang value="rust">

```rust

```

</Lang>
</CodeTabs>

The `app_custom_peer_info` field is yours: put a JSON blob or tag there to coordinate between instances of your own application across the session.

## Enumerating peers

In C this is a count-then-fetch, like every enumeration in the API. In C# the same enumeration returns a ready-made array:

<CodeTabs>
<Lang value="c">

```c
size_t count = 0;
qar_result_log_if_error(qar_query_peer_specs_count(session, &count));

QarPeerSpec** specs = malloc(count * sizeof(*specs));
qar_result_log_if_error(
    qar_query_peer_specs(session, specs, count, &count));

for (size_t i = 0; i < count; ++i)
{
    char name[128];
    qar_peer_spec_get_display_name(specs[i], name, sizeof(name));
    /* also: _get_app_version, _get_app_custom_peer_info,
             _get_presence, _get_version_id, _get_room_tag,
             _get_id, _get_role, _get_category, _get_device_id,
             _get_device_family, _get_device_name */
    qar_peer_spec_handle_destroy(specs[i]);
}
free(specs);
```

</Lang>


The binding does not wrap the presence, role, category and device identity getters (`qar_peer_spec_get_presence` and the others): they are raw only, through `library.raw_api()` with the session's `as_raw()`. `PeerInfo` carries the app state, which the header derives from the presence. Reading the presence itself, raw:

```rust
// The presence is raw only: query the peer specs through the raw table with the session's
// handle. Every peer spec the query hands out is yours to destroy.
let api = library.raw_api();
let mut peers: [*mut QarPeerSpec; 64] = [std::ptr::null_mut(); 64];
let mut written = 0_usize;
// SAFETY: the session is alive and used on this thread; each spec handle is used before
// it is destroyed, and every buffer is writable for the length passed with it.
unsafe {
    let result = (api.qar_impl_query_peer_specs)(
        session.as_raw(),
        peers.as_mut_ptr(),
        peers.len(),
        &raw mut written,
    );
    (api.qar_impl_result_log_if_error)(result);
    for &peer in &peers[..written] {
        let mut presence = QarPeerPresence::QAR_PEER_PRESENCE_UNKNOWN;
        (api.qar_impl_peer_spec_get_presence)(peer, &raw mut presence);
        // Render for ONLINE peers and UNKNOWN ones (not reconciled yet); stop at OFFLINE,
        // LEAVING or RETIRED. OFFLINE and LEAVING peers may come back as ONLINE.
        let is_here = presence == QarPeerPresence::QAR_PEER_PRESENCE_ONLINE
            || presence == QarPeerPresence::QAR_PEER_PRESENCE_UNKNOWN;
        render_for(peer, is_here);
        (api.qar_impl_peer_spec_handle_destroy)(peer);
    }
}
```

The role, category and device getters follow in the next sections.

</Lang>
</CodeTabs>

Useful fields:

- **presence** — `qar_peer_spec_get_presence()` (`PeerSpec.Presence` in C#): whether the peer is here. Render for, wait for and count `QAR_PEER_PRESENCE_ONLINE` and `QAR_PEER_PRESENCE_UNKNOWN` peers; stop at `OFFLINE`, `LEAVING` or `RETIRED`.

  | Presence | Means |
  |---|---|
  | `ONLINE` | the hub sees the peer in the session |
  | `OFFLINE` | the hub no longer sees it: a crash, a kill, a network loss or a short drop. It reads `ONLINE` again once it is back |
  | `LEAVING` | it announced a clean exit, and may come back under the same id |
  | `RETIRED` | it left for good; query results no longer list it |
  | `UNKNOWN` | the hub has not reconciled it yet (an older hub that never reports presence, or one that just started); nothing says it is gone, so treat it like `ONLINE` |

- **app state** (deprecated) — `qar_peer_spec_get_app_state()` / `PeerSpec.AppState` still work and are computed from the presence, but every peer reads `QAR_APP_STATE_RUNNING` from the moment it joins, so the value never tells "loading" from "ready". Read the presence instead.
- **room tag** — which physical room the peer is in; lets multi-room deployments group peers.
- **`qar_session_get_my_spec`** — your own peer's spec (e.g. to learn your assigned peer ID).

## What a peer is: role, category and device

Every peer describes itself with five values. Read them from any `QarPeerSpec`, or from `PeerSpec` in C#:

| Value | C getter | C# | Example | Meaning |
|---|---|---|---|---|
| Role | `qar_peer_spec_get_role` | `Role` | `QAR_PEER_ROLE_TARGET` | What the peer does: `SOURCE` (renders or captures), `TARGET` (shows rendered content), `RUNTIME` (a Hub), `CONTROL` (a visualizer's control session), `INTERNAL` (pipeline infrastructure such as the mixer) |
| Category | `qar_peer_spec_get_category` | `Category` | `QAR_DEVICE_CATEGORY_HEADSET` | The kind of device: `HEADSET`, `CAMERA`, `VISUALIZER`, `DESKTOP_PC`, `SERVER`, or `UNKNOWN` |
| Device id | `qar_peer_spec_get_device_id` | `DeviceId` | `"MetaQuest3"` | The exact model, when known |
| Device family | `qar_peer_spec_get_device_family` | `DeviceFamily` | `"MetaQuest"` | The model's family |
| Device name | `qar_peer_spec_get_device_name` | `DeviceName` | `"Meta Quest 3"` | What to show the user |

- Render for peers whose role is `TARGET`; the category and device only say *what* the target is.
- **Ids and families are open strings**, not an enum: new models appear without a new QAROS SDK. Today's families include `HoloLens`, `MetaQuest`, `Metalens`, `Headset` (a headset that has not reported a known model) and `Zed`; treat this list as examples, never as complete.
- Pick a picture or model by device id, else by family, else by category. An unknown model of a known family still matches its family; an unknown family still matches its category.
- **The identity can change while the peer runs.** A headset first joins as the kind it was invited as (`HoloLens` or `Headset`) and is refined to the exact model once its device answers. Re-read it in your `qar_peer_subscribe_updates` callback instead of caching it.
- The C string getters fill a caller buffer, like `qar_peer_spec_get_display_name`. Text is UTF-8.

### Show the user what each target is

<CodeTabs>
<Lang value="c">

```c
QarPeerSpec* peers[64];
size_t written = 0;
qar_result_log_if_error(qar_query_peer_specs(session, peers, 64, &written));

for (size_t i = 0; i < written; ++i)
{
    QarPeerRole role = QAR_PEER_ROLE_INTERNAL;
    QarDeviceCategory category = QAR_DEVICE_CATEGORY_UNKNOWN;
    char name[128] = "", family[64] = "";
    if (qar_result_is_success(qar_peer_spec_get_role(peers[i], &role))
        && role == QAR_PEER_ROLE_TARGET)
    {
        qar_peer_spec_get_category(peers[i], &category);
        qar_peer_spec_get_device_name(peers[i], name, sizeof(name));       /* "Meta Quest 3" */
        qar_peer_spec_get_device_family(peers[i], family, sizeof(family)); /* "MetaQuest"    */
        show_target(name, icon_for(family, category)); /* your icon table, category as fallback */
    }
    qar_peer_spec_handle_destroy(peers[i]);
}
```

</Lang>
<Lang value="rust">

The role, category and device getters are raw only: call them through `library.raw_api()` with the session's `as_raw()`.

```rust
// The role, category and device getters are raw only: call the raw table with the
// session's handle. Every peer spec the query hands out is yours to destroy.
let api = library.raw_api();
let mut peers: [*mut QarPeerSpec; 64] = [std::ptr::null_mut(); 64];
let mut written = 0_usize;
// SAFETY: the session is alive and used on this thread; each spec handle is used before
// it is destroyed, and every buffer is writable for the length passed with it.
unsafe {
    let result = (api.qar_impl_query_peer_specs)(
        session.as_raw(),
        peers.as_mut_ptr(),
        peers.len(),
        &raw mut written,
    );
    (api.qar_impl_result_log_if_error)(result);
    for &peer in &peers[..written] {
        let mut role = QarPeerRole::QAR_PEER_ROLE_INTERNAL;
        let mut category = QarDeviceCategory::QAR_DEVICE_CATEGORY_UNKNOWN;
        let (mut name, mut family) = ([0 as c_char; 128], [0 as c_char; 64]);
        let role_read = (api.qar_impl_peer_spec_get_role)(peer, &raw mut role);
        if (api.qar_impl_result_is_success)(role_read)
            && role == QarPeerRole::QAR_PEER_ROLE_TARGET
        {
            (api.qar_impl_peer_spec_get_category)(peer, &raw mut category);
            (api.qar_impl_peer_spec_get_device_name)(peer, name.as_mut_ptr(), name.len());
            (api.qar_impl_peer_spec_get_device_family)(peer, family.as_mut_ptr(), family.len());
            let name = CStr::from_ptr(name.as_ptr()).to_string_lossy(); // "Meta Quest 3"
            let family = CStr::from_ptr(family.as_ptr()).to_string_lossy(); // "MetaQuest"
            show_target(&name, &family, category); // your icon table, category as fallback
        }
        (api.qar_impl_peer_spec_handle_destroy)(peer);
    }
}
```

## Describing your own device

An application is always a **source** (`QAR_PEER_ROLE_SOURCE`): it describes its device, never its role. By default QAROS publishes it as a desktop PC (`DesktopWindows` / `DesktopLinux`). To say more, chain a `QarPeerDeviceIdentity` on `QarPeerPresentation::header.next` when you onboard or rejoin:

- `category` must be `QAR_DEVICE_CATEGORY_DESKTOP_PC`, `QAR_DEVICE_CATEGORY_SERVER` or `QAR_DEVICE_CATEGORY_CAMERA`. Anything else fails with `QAR_STATUS_PEER_DEVICE_CATEGORY_NOT_ALLOWED` and changes nothing.
- `device_id` is required. `device_family` and `device_name` are optional. An id the Hub's device catalog does not know is fine: the visualizer shows it by family or category, with your name.
- Chain the same extension on `QarRejoinInit` to keep it across restarts.

### A source app that is a camera

<CodeTabs>
<Lang value="c">

```c
QarPeerDeviceIdentity identity = {
    .header = { .type = QAR_STRUCTURE_TYPE_PEER_DEVICE_IDENTITY },
    .category = QAR_DEVICE_CATEGORY_CAMERA,
    .device_id = "LuxonisOakD",   /* unknown ids are fine */
    .device_family = "Luxonis",
    .device_name = "Luxonis OAK-D",
};

QarOnboardInit init = qar_onboard_init_default();
QarOnboardLocalAppExt local = qar_onboard_local_app_ext_default();
init.header.next = &local.header;
init.presentation.display_name = "Lab camera 1";
init.presentation.header.next = &identity.header;

QarOnboardingId unused = qar_onboarding_id_default();
QarSession* session = NULL;
QarResult r = qar_runtime_onboard(runtime, &init, NULL, NULL,
                                  cancel, &unused, &session);
/* Joins as Source + Camera + LuxonisOakD. */
```

</Lang>
<Lang value="rust">

Declaring your device is raw only: onboard through `library.raw_api()` with the runtime's `as_raw()`. The session it returns is a raw `QarSession`, not a `qaros::Session`.

```rust
// Declaring your device is raw only: onboard through the raw table with the runtime's
// handle. The session it hands out is raw too: not a qaros::Session, so destroy it with
// qar_session_handle_destroy before the runtime drops.
let api = library.raw_api();
let identity = QarPeerDeviceIdentity {
    header: defaults::structure_header(
        QarStructureType::QAR_STRUCTURE_TYPE_PEER_DEVICE_IDENTITY,
    ),
    category: QarDeviceCategory::QAR_DEVICE_CATEGORY_CAMERA,
    device_id: c"LuxonisOakD".as_ptr(), // unknown ids are fine
    device_family: c"Luxonis".as_ptr(),
    device_name: c"Luxonis OAK-D".as_ptr(),
};

let mut init = defaults::qar_onboard_init_default();
let mut local = defaults::qar_onboard_local_app_ext_default();
init.header.next = (&raw mut local.header).cast();
init.presentation.display_name = c"Lab camera 1".as_ptr();
init.presentation.header.next = (&raw const identity.header).cast_mut().cast();

let mut unused = defaults::qar_onboarding_id_default();
let mut session: *mut QarSession = std::ptr::null_mut();
// SAFETY: the runtime is alive and used on this thread; init and its chain live on this
// stack frame for the whole call; the out-pointers are valid.
let result = unsafe {
    (api.qar_impl_runtime_onboard)(
        runtime.as_raw(),
        &raw const init,
        None,
        std::ptr::null_mut(),
        cancel.as_raw(),
        &raw mut unused,
        &raw mut session,
    )
};
// SAFETY: plain value argument.
unsafe { (api.qar_impl_result_log_if_error)(result) };
// Joins as Source + Camera + LuxonisOakD.
```

## Reacting to changes

<CodeTabs>
<Lang value="c">

```c
static void on_peer_update(/* peer update info */ ..., void* state)
{
    /* peer joined / left / changed presentation or presence */
}

qar_peer_subscribe_updates(session, on_peer_update, NULL);
```

</Lang>
<Lang value="csharp">

```csharp
// As a C# event: fires on the library thread — marshal to your own thread.
session.Peers.Updated += (sender, e) =>
{
    PeerSpec peer = e.Peer; // joined / left / changed presentation or presence
};

// Or as a disposable subscription — Dispose() stops native delivery:
Result<IDisposable> sub = session.Peers.SubscribeUpdates(
    peer => { /* ... */ });
using IDisposable subscription = sub.ValueOrThrow();
```

</Lang>
<Lang value="rust">

{/* Generated by cargo xtask guide from examples/guide/peers.md of the Rust binding. Edit that file, not this tab. */}

```rust
// Runs on a library thread: forward to your own thread before touching app state.
let subscription = session.subscribe_peer_updates(|peer: PeerInfo| {
    // peer joined / left / changed presentation or app state
    println!("{} is {:?}", peer.display_name, peer.app_state);
})?;

// Or into a std::sync::mpsc receiver you drain on your own thread:
let (forward, updates) = qaros::channel();
let forwarding = session.subscribe_peer_updates(forward)?;
for peer in updates.try_iter() {
    println!("{}", peer.display_name);
}

// Dropping a Subscription stops delivery; detach() keeps it for the session's lifetime.
```

</Lang>
</CodeTabs>

Typical uses: refresh a "participants" panel, start a [render stream](/docs/developer-guide/rendering-streams) when a target device appears, or pause expensive rendering when the last viewer leaves. Callback threading rules apply as everywhere: see [API Conventions](/docs/developer-guide/api-conventions#4-blocking--async-pairs).

# App Volumes and Gestures

<LanguageSwitcher />

An **app volume** is your application's home in the room: a named 3D box that holds your rendered content, defines where the mixer composites your stream, and mediates how users grab, move, and scale your content. Read the conceptual model first: [The QAROS World](/docs/user-guide/qaros-world#app-volumes) and [Coordinate Systems](/docs/developer-guide/coordinate-systems).

## Creating a volume (idempotent)

Like panels, volumes are identified by a stable **common name**:

:::warning Required display name
Set both the stable ASCII common name (`common_name` / `CommonName`) and a non-empty user-facing label (`display_name` / `DisplayName`) when creating or reopening a volume. The common name supplies identity; it is not a fallback label. C# option constructors leave `DisplayName` null, so set it explicitly in the initializer even though the property is nullable. An already open object may ignore creation options, which can hide an omitted label until a clean install or reopen.
:::

<CodeTabs>
<Lang value="c">

```c
QarAppVolumeInit init = qar_app_volume_init_default();
init.common_name = "assembly-view.myapp.example.com";
init.display_name = "Assembly View";

init.pose = qar_pose_default();          /* cuboid CENTER, room space   */
init.pose.position.y = 1.2f;

QarAppVolumeSize size = qar_app_volume_size_default();
size.width_meters = 1.0f;
size.length_meters = 1.0f;
size.height_meters = 0.8f;
init.size = size;

init.app_pose = qar_pose_default();      /* app origin inside the box   */
init.app_scale = 0.01f;                  /* 1 app-meter -> 1 room-cm:
                                            a 100 m model fits the box  */

QarAppVolumeId volume_id;
qar_result_log_if_error(
    qar_app_volumes_get_or_create(session, &init, &volume_id));
```

</Lang>

The `volume_id` is what you pass to the render sender (`QarRenderSenderInit.app_volume_id`) so your stream is composited inside this box — see [Rendering Streams](/docs/developer-guide/rendering-streams).

- **A restart takes the volume over.** The id derives from the common name, so after a restart `get_or_create` returns the volume your previous run left, ignores the creation options, and from then on your session carries it into the hub's next session like one it created.
- **Call it again when the session changes.** On a new session id, and after onboarding again on `RE_PAIR_REQUIRED`, call `get_or_create` again for every common name your app owns: it returns the same id and re-creates the volume when it is missing. See [When the hub's session changes](/docs/developer-guide/onboarding-and-sessions#when-the-hubs-session-changes).

## The two transforms, in practice

- **Volume in the room:** `qar_app_volumes_change_pose` / `_change_size` move and resize the box itself (users usually do this by grabbing the volume).
- **Content in the volume:** `qar_app_volumes_change_app_pose` / `_change_app_scale` pan and zoom your content *inside* the box, without your renderer changing anything. `app_pose` is in volume meters (unscaled); `app_scale` is room-meters per app-meter.

Because other peers (and gestures) can change these too, read the *live* values with the `latest` getters: `qar_app_volume_get_latest_pose`, `_latest_size`, `_latest_app_pose`, `_latest_app_scale` — and subscribe with `qar_app_volumes_subscribe_updates`.

## World anchors

To publish an Earth-fixed reference frame with a volume (ECEF WGS84; see [Coordinate Systems](/docs/developer-guide/coordinate-systems#world-space--a-geographic-reference)):

<CodeTabs>
<Lang value="c">

```c
QarGeoAnchorFrame frame;
frame.world_ref_system = QAR_WORLD_REF_SYSTEM_ECEF_WGS84_METERS;
frame.handedness = QAR_HANDEDNESS_RIGHT; /* required: UNSPECIFIED is rejected */
/* fill origin_world (meters, ECEF) and the axis_x/y/z_world unit vectors */
qar_app_volumes_change_app_world_anchor(session, &volume_id, &frame);
/* ... */
qar_app_volumes_clear_app_world_anchor(session, &volume_id);
```

</Lang>
<Lang value="rust">

World anchors are raw only: call them through `library.raw_api()` with the session's `as_raw()`.

```rust
// World anchors are raw only: call the raw table with the session's handle.
let api = library.raw_api();
let volume = QarAppVolumeId { data: volume_id.0 };
let frame = QarGeoAnchorFrame {
    world_ref_system: QarWorldReferenceSystem::QAR_WORLD_REF_SYSTEM_ECEF_WGS84_METERS,
    handedness: QarHandedness::QAR_HANDEDNESS_RIGHT, // required: UNSPECIFIED is rejected
    origin_world: origin,                            // meters, ECEF
    axis_x_world: east,                              // unit vectors
    axis_y_world: up,
    axis_z_world: south,
};
// SAFETY: the session is alive and used on this thread; the id and frame outlive the call.
let result = unsafe {
    (api.qar_impl_app_volumes_change_app_world_anchor)(
        session.as_raw(),
        &raw const volume,
        &raw const frame,
    )
};
// SAFETY: plain value argument.
unsafe { (api.qar_impl_result_log_if_error)(result) };
// ...
// SAFETY: as above.
let result = unsafe {
    (api.qar_impl_app_volumes_clear_app_world_anchor)(session.as_raw(), &raw const volume)
};
// SAFETY: plain value argument.
unsafe { (api.qar_impl_result_log_if_error)(result) };
```

</Lang>
</CodeTabs>

`AppWorldAnchor` is shared geographic reference metadata. The current SDK stores and replicates it, but setting or clearing it does not move the box, modify `AppPose`/`AppScale`, transform render-sender view poses, or enable automatic geographic reprojection. Applications implement the required geographic mapping and room alignment.

Keep the units separate:

- `origin_world` is an absolute ECEF position in meters; each axis is a unit direction vector.
- `AppPose.Position` is a Euclidean offset in **volume meters**, relative to the box center. It is neither an ECEF position nor an Earth-frame offset, and `AppScale` does not scale this stored translation.
- Render-sender view poses and gesture points use **app-content units**, after the inverse volume/app transforms and division by `AppScale`.

If render-coordinate units differ from world meters, publish a separate application-specific conversion, such as `worldMetersPerAppUnit = S0`. Unit axes cannot encode that scale. A custom snapshot may group this value and the anchor under a name such as `appCoordinate`; that is an integration protocol, not an SDK property. Do not encode `S0` in non-unit axes or streaming `depth_scale`. A one-to-one local-Earth-meter interpretation requires actual world-meter app coordinates and a consumer-defined mapping to the anchor; the anchor alone does not establish that mapping. See [World space](/docs/developer-guide/coordinate-systems#world-space--a-geographic-reference).

The compiled tutorial builds a full east/up/south frame from a latitude/longitude: [Publish a World Anchor](/docs/developer-guide/tutorials/c/app-volume-management).

## Coordination between users

- **Editing lock:** `qar_app_volumes_start_editing` / `_stop_editing` mark the volume busy; `qar_app_volume_get_editing_status` tells everyone *which peer* is editing, so UIs can show "Alice is moving this".
- **Used-by peers:** `qar_app_volumes_update_used_by_peers` maintains the set of peers actively using the volume (`_get_used_by_peers_count` / `_get_used_by_peers` to read).
- **Lifetime:** `qar_app_volumes_close_volume` retires the volume; `qar_app_volume_get_lifetime_status` distinguishes active from closed.

## Gestures

The gesture system turns hand interactions into either **automatic content transforms** or **events your app consumes**. You configure it per volume with a prioritized list of mapping rules (`QarAppVolumeGestureConfiguration`, settable at init or via `qar_app_volumes_change_gesture_configuration`).

Gesture kinds: click, hover, single-pointer 6-DoF drag, dual-pointer distance (pinch-zoom), dual-pointer rotate.

Each `QarAppVolumeGestureMappingRule` chooses:

- **target** — map the gesture onto `app_pose` or `app_scale` (built-in pan/zoom), or leave it to your app,
- **axes** — bitmask constraining translation/rotation axes,
- **precision** — hand-centimeters per app-centimeter (values above 1 give fine control),
- **scale sensitivity** — constant, inverse-to-app-scale, or proportional-to-app-scale, so zoom feels right at any magnification,
- whether the gesture works from outside the volume, and the controller-ray style.

The default configuration already gives you grab-to-move (6-DoF → `app_pose`) and pinch-to-zoom (distance → `app_scale`, proportional). To change it, start from `qar_app_volume_gesture_configuration_default()` and edit rules in place — worked in [Customise the Gesture Configuration](/docs/developer-guide/tutorials/c/app-volume-management).

To consume gestures yourself — e.g. clicking parts of your model — subscribe:

<CodeTabs>
<Lang value="c">

```c
static void on_gesture(QarAppVolumeGesture* g, void* state)
{
    /* g is valid only during this call - copy what you keep */
    QarPeerId peer; QarAppVolumeId volume;
    QarGestureKind kind; QarGesturePhase phase;
    QarVector3 action, start; bool has_action, has_start;
    qar_app_volume_gesture_get_lifecycle(g, &peer, &volume);
    qar_app_volume_gesture_get_classification(g, &kind, &phase);
    qar_app_volume_gesture_get_points(g, &action, &has_action, &start, &has_start);
    /* qar_app_volume_gesture_get_deltas: accumulated deltas in app volume
       space, plus whether the library already applied them to app_pose/scale */
}

qar_app_volumes_subscribe_all_gesture_events(session, &volume_id, on_gesture, NULL, NULL);
```

</Lang>
<Lang value="rust">

{/* Generated by cargo xtask guide from examples/guide/app-volumes.md of the Rust binding. Edit that file, not this tab. */}

Gestures are raw only: subscribe through `library.raw_api()` with the session's `as_raw()` and a callback of your own. The subscription belongs to its cancel token: it ends when you call `cancel()` on the token, when the token's last clone drops (the drop destroys the handle, which ends it too), or when the session drops.

```rust
/// Runs on a library thread. `gesture` is valid only during this call: copy what you keep.
/// The library table travels as the user state.
unsafe extern "C" fn on_gesture(gesture: *mut QarAppVolumeGesture, user_state: *mut c_void) {
    // SAFETY: the user state is the table subscribe_gestures passed, alive while the library is.
    let api = unsafe { &*user_state.cast::<qaros::qaros_sys::QarApi>() };
    let mut peer = defaults::qar_peer_id_default();
    let mut volume = defaults::qar_app_volume_id_default();
    let mut kind = QarGestureKind::QAR_GESTURE_CLICK;
    let mut phase = QarGesturePhase::QAR_GESTURE_PHASE_STARTED;
    let (mut action, mut start) = (
        defaults::qar_vector3_default(),
        defaults::qar_vector3_default(),
    );
    let (mut has_action, mut has_start) = (false, false);
    // SAFETY: the gesture is valid during the callback; every out-pointer is valid.
    unsafe {
        (api.qar_impl_app_volume_gesture_get_lifecycle)(gesture, &raw mut peer, &raw mut volume);
        (api.qar_impl_app_volume_gesture_get_classification)(
            gesture,
            &raw mut kind,
            &raw mut phase,
        );
        (api.qar_impl_app_volume_gesture_get_points)(
            gesture,
            &raw mut action,
            &raw mut has_action,
            &raw mut start,
            &raw mut has_start,
        );
    }
    // qar_app_volume_gesture_get_deltas: accumulated deltas in app volume space, plus whether
    // the library already applied them to app_pose/scale
}

// Gestures are raw only: subscribe through the raw table with the session's handle. The
// returned token owns the subscription.
let api = library.raw_api();
let volume = QarAppVolumeId { data: volume_id.0 };
let subscription = library.create_cancel_token(None)?;
// SAFETY: the session is alive and used on this thread; the user state (the table) lives
// as long as the library, which outlives the session.
let result = unsafe {
    (api.qar_impl_app_volumes_subscribe_all_gesture_events)(
        session.as_raw(),
        &raw const volume,
        Some(on_gesture),
        std::ptr::from_ref(api).cast_mut().cast(),
        subscription.as_raw(),
    )
};
// SAFETY: plain value argument.
unsafe { (api.qar_impl_result_log_if_error)(result) };

// Ends the subscription: no gesture callback starts after this returns, and one running on
// another thread has returned. Dropping the token's last clone ends it as well.
subscription.cancel()?;
```

</Lang>
</CodeTabs>

Gesture start and action points already arrive in **app content space** (as do a render sender's view poses and hands) (app units, under the app pose and scale the gesture began with), so hit-test them against your model directly. A point you hold only in **room space** — a GUI panel position, a device pose — goes through two steps: room → app volume space via the volume's latest pose (its position is the cuboid **center**, so the box spans ± half the extents), then app volume → app content space via `app_pose` and `app_scale`. The compiled tutorial implements both steps and the cuboid test: [Room-Space Point to App Content Space](/docs/developer-guide/tutorials/c/app-volume-management).

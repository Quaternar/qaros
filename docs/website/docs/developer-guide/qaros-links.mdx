# qaros:// Links

<LanguageSwitcher />

Your app can send the user straight to a place in QAROS: the QR code a headset pairs with, the QR code a device anchors its room with, or the setup steps of one device type. You open a `qaros://` link the way you open any web link; no API call and no session are needed.

- QAROS starts if it is not running, and the link is shown once it is ready.
- While the Visualizer is hidden (QAROS running in the tray), only the dialog the link names comes up, as a window of its own: the dialog fills it, its title bar shows the dialog's title, and the user can move, resize, minimize or maximize it like any window. Closing the window closes the dialog and hides it again.
- While the Visualizer is open, the dialog opens on top of it.
- If the dialog cannot open (for example, a pairing is already running), the Visualizer opens instead and says why.

Links work on Windows, where the QAROS installer registers the `qaros` scheme. Linux support is planned.

## The links

| Link | Opens |
|---|---|
| `qaros://visualizer/v1/devices/pair-qr` | **Pair Headset** dialog: the QR code and a field for the code shown on the headset. The QAROS Player on a headset scans the QR code to join, or you type the code and address the headset shows. A fresh single-use QR code is made each time; a dialog already on screen is brought to the front instead. |
| `qaros://visualizer/v1/scene-origin/qr` | **Room Origin**: the anchoring QR code a device scans to place the room origin, with **Print** and **Save as PDF...** in the same dialog. |
| `qaros://visualizer/v1/devices/setup?kind=<kind>` | **Set up a device**: the setup steps of one device type, the same as in the Devices tab. |

`<kind>` is one of:

| `kind` | Device type |
|---|---|
| `quest` | Meta Quest |
| `metalens` | Metalens |
| `android-xr` | Android XR headsets |
| `hololens` | HoloLens |

## Rules

A link opens a dialog and nothing else: it never pairs, installs, changes a setting or carries data. Anything that is not exactly one of the links above is ignored, so check your link against the table.

- `v1` is the link version. A link of a version this QAROS does not know is ignored and logged as made for a newer QAROS.
- `qaros://visualizer` may be written in any case; the rest is lowercase, exactly as shown.
- One trailing `/` after the place is accepted (`.../pair-qr/`).
- Ignored: unknown places or kinds, any other parameter, a parameter repeated, a parameter on a place that takes none, a `#fragment`, a port or user name, percent-encoded characters, spaces or non-ASCII characters, and links longer than 256 characters.

## Opening a link from your app

Hand the link to the operating system. It starts the program registered for `qaros://` links, which passes the link to QAROS.

<CodeTabs>
<Lang value="c">

```c
#include <windows.h>
#include <shellapi.h>

/* Opens the setup of a Meta Quest in QAROS; QAROS starts if it is not running. */
HINSTANCE opened = ShellExecuteW(
    NULL, L"open", L"qaros://visualizer/v1/devices/setup?kind=quest", NULL, NULL, SW_SHOWNORMAL);
if ((INT_PTR)opened <= 32)
{
    /* No program is registered for qaros:// links: QAROS is not installed. */
}
```

A web page can link to the same URLs (`<a href="qaros://visualizer/v1/devices/pair-qr">Pair a headset</a>`); the browser asks the user once whether to open QAROS. From a terminal: `start "" "qaros://visualizer/v1/scene-origin/qr"`.

## Several QAROS on one PC

The operating system has one handler for `qaros://` links, and it hands a link to the **most recently started** QAROS of the session. That is the right guess for a web page, but not for an app that a QAROS started itself: a development hub of one worktree, a build folder started by hand and the installed QAROS can run side by side, and each starts its apps with `QAR_INSTANCE=<name>` (`default` for the installed QAROS, `dev-<hash>` for a development hub).

An app that was started by QAROS opens a link for **its own** QAROS instead: it starts that instance's tray, `qaros.exe`, with `--own-instance` and the link.

```
"<tray of QAR_INSTANCE>\qaros.exe" --own-instance "qaros://visualizer/v1/devices/pair-qr"
```

- The tray of the instance is the `RuntimeFolder` value of `HKCU\SOFTWARE\Quaternar\QAROS\Instances\<name>` (a development hub), else the `bin` folder of that record's `InstallFolder`; for `default`, the `bin` folder of `InstallFolder` in `HKLM\SOFTWARE\Quaternar\QAROS`. It is the same folder the runtime of that instance loads from.
- The tray gives the link to the running QAROS of its own instance, and to no other. If that QAROS is not running, it starts and then shows the link.
- Start the tray without the inherited `QAR_APP_DATA_ROOT` and `QAR_LOCAL_ENROLLMENT_PIPE`, so it works out its own data folder.
- The link itself is the same one as in the table above: there is no `instance` parameter, and a link that another process or a web page writes cannot choose an instance.
- If `QAR_INSTANCE` is set but its tray cannot be found (the instance is not installed, or its build folder is gone), report the error; do not fall back to the system handler, which could open a different QAROS.
- If `QAR_INSTANCE` is not set, your app was not started by QAROS: open the link through the system handler as shown above. It goes to the most recently started QAROS.

The TerraExplorer add-on does this for its own panel buttons (Set up Meta Quest, METALENSE and Android XR, Show anchoring QR, Show headset onboarding QR).

# Render Loops

<LanguageSwitcher />

A render sender serves one viewer (a headset, a visualizer view). Your application serves every viewer that joins with a sender of its own, from one loop or one thread per viewer. This page shows the three ways to drive those senders, what each costs, and when to choose it. The sender itself — layouts, textures, show parameters — is in [Rendering Streams](/docs/developer-guide/rendering-streams).

## Two modes: who decides when to render

| Mode | Begin-frame waits for | The poses are for | Fits |
|---|---|---|---|
| **Request-driven** (default) | The viewer's render request, which the mixer times for the display tick it needs | The display time the request names, predicted again when you first read the pose | Applications that can render when asked |
| **Free-running** | Only a free destination; the viewer keeps one ready | Predicted from the newest head pose for when the frame will be shown | Applications whose render loop runs at its own rate (a game loop, an engine's frame) |

Why both exist:

- **Request-driven** lets the mixer decide: it knows each viewer's display rate and when its next tick is, so it asks for each frame just in time, and your application renders exactly what each viewer will show.
- **Free-running** lets your application decide: many engines own their frame loop and cannot wait for a request. The sender then hands you the poses whenever you render, and the viewer keeps a destination ready for the result.

In both modes the pose you read is predicted for when the frame will be **shown**: a request your loop took late is rendered that much further ahead, so a late read costs you no pose accuracy.

## Creating a sender in each mode

You choose the mode when you create the sender. Request-driven is the default; free-running chains the render loop extension:

## Implementing the request-driven mode

The viewer asks for each frame; your application answers it. Every loop here renders for a viewer only after its request is in, and handles each stream state as [Stream states](#stream-states) lists.

### Serving several viewers

Every loop on this page, request-driven or free-running, serves a **collection of senders**, one per viewer. A viewer is a peer whose role is target; it joins when it comes online and leaves when it goes offline ([Finding rendering targets](/docs/developer-guide/rendering-streams#finding-rendering-targets)). Peer updates arrive on a library thread: queue them, and create and destroy senders on the render thread.

<CodeTabs>
<Lang value="c">

```c
/* Library thread: queue the viewer for the render thread. */
static void on_peer(QarPeerSpec* peer, void* user_state)
{
    QarPeerRole role = QAR_PEER_ROLE_INTERNAL;
    QarPeerPresence presence = QAR_PEER_PRESENCE_UNKNOWN;
    QarPeerId id = qar_peer_id_default();
    if(qar_result_is_error(qar_peer_spec_get_role(peer, &role)) || role != QAR_PEER_ROLE_TARGET
       || qar_result_is_error(qar_peer_spec_get_presence(peer, &presence))
       || qar_result_is_error(qar_peer_spec_get_id(peer, &id)))
        return;
    bool online = presence == QAR_PEER_PRESENCE_ONLINE || presence == QAR_PEER_PRESENCE_UNKNOWN;
    viewer_queue_push(user_state, id, online);   /* your thread-safe queue */
}

/* Render thread, once per pass: add joined viewers, drop the ones that left. */
static void update_viewers(Viewers* viewers)
{
    QarPeerId id;
    bool online;
    while(viewer_queue_pop(&viewers->queue, &id, &online))
    {
        Viewer* viewer = viewers_find(viewers, id);
        if(online && viewer == NULL)
            viewers_add(viewers, id, create_sender_for(id));  /* Rendering Streams */
        else if(!online && viewer != NULL)
            drop_viewer(viewers, viewer);
    }
}

/* Releases the viewer's frame and sender. Its next online update serves it again. */
static void drop_viewer(Viewers* viewers, Viewer* viewer)
{
    if(viewer->ready != NULL)
        qar_render_frame_info_handle_destroy(viewer->ready);
    qar_render_stream_handle_destroy(viewer->sender);
    viewers_remove(viewers, viewer);
}
```

### Blocking: one thread per viewer

`begin_frame` waits for the viewer's request, you render with the poses it hands out, and show.

<CodeTabs>
<Lang value="c">

```c
/* One thread per viewer, started when the viewer joins. */
static void viewer_thread(Viewer* viewer)
{
    while(!viewer->leaving)
    {
        QarRenderFrameInfo* info = NULL;
        QarResult r = qar_render_sender_begin_frame(viewer->sender, viewer->cancel, &info);
        if(r.code == QAR_STATUS_RENDERING_PRODUCER_STREAM_IS_CLOSED)
            break;                    /* gone: the thread's owner destroys the sender */
        if(qar_result_is_error(r))
            continue;                 /* reconnecting, not set up yet, cancelled: retry */
        render_views(viewer, info);   /* your renderer, with the poses in info */
        show(viewer->sender);         /* also when rendering failed */
        qar_render_frame_info_handle_destroy(info);
    }
}

static void show(QarRenderSender* sender)
{
    QarRenderFrameShow frame_show = qar_render_frame_show_default();
    frame_show.rendered_near_far.near_plane = 0.1f;
    frame_show.rendered_near_far.far_plane = 100.0f;
    qar_result_log_if_error(qar_render_sender_show_frame(sender, &frame_show));
}
```

`begin_owned_frame` is the blocking begin-frame; `begin_frame` is the same with a frame that borrows the sender.

```rust
// One thread per viewer, started when the viewer joins.
while !leaving() {
    let mut frame = match sender.begin_owned_frame(&BlockingOptions::default()) {
        Ok(frame) => frame,
        // Gone: the thread's owner drops the sender.
        Err(error) if error.has_code(StatusCode::RENDERING_STREAM_IS_CLOSED) => break,
        Err(_reconnecting_or_not_set_up_yet) => continue,
    };
    let views = views_of(&frame)?;
    render_views(&mut frame.cpu_frame()?, &views); // your renderer
    frame.show(&ShowParams::default())?; // also when rendering failed
}
```

</Lang>

- **Pros:** the simplest code; the mixer paces each viewer exactly, so each frame is rendered just in time for its tick.
- **Cons:** one thread per viewer. Threads must not share a renderer that serialises them, or the slowest viewer sets every viewer's rate. In one thread serving several viewers in turn, each `begin_frame` waits for its viewer, and a paused viewer blocks the whole loop until it resumes.
- **Choose it** for a single viewer, or a renderer that can render for each viewer on its own thread.

### Non-blocking: one loop for every viewer

Poll each sender with `try_begin_frame`; render only for the viewers whose frame is ready, and skip the rest.

The [Vulkan cube example](https://github.com/Quaternar/qaros/tree/main/qar-streaming-c/examples/vulkan_cube) implements this loop in C++ on the C API with `--render-loop request-driven`, on a fixed schedule (`--fps <n>`, default 60) or as fast as the viewers take frames (`--uncapped`).

**Arm the next wait right after you show.** The first `try_begin_frame` call starts the wait for the viewer's next request, and only a later call can find it complete. Call it once more right after `show_frame`, so the wait runs while your loop is idle and the next pass finds the frame ready. Started only at the next pass, the wait completes one pass later, and a loop at its own rate (say 30 fps) serves every viewer every other frame. A frame the arming call already returns is kept for the next pass.

<CodeTabs>
<Lang value="c">

```c
typedef struct Viewer
{
    QarPeerId id;
    QarRenderSender* sender;
    QarRenderFrameInfo* ready;   /* a frame begun and not yet rendered */
} Viewer;

typedef enum Poll { POLL_FRAME, POLL_NOT_NOW, POLL_CLOSED } Poll;

/* Never blocks. POLL_FRAME leaves the frame in viewer->ready. */
static Poll poll_frame(Viewer* viewer)
{
    if(viewer->ready != NULL)
        return POLL_FRAME;   /* came back when the last show armed it */
    bool ready = false;
    QarResult r = qar_render_sender_try_begin_frame(viewer->sender, &viewer->ready, &ready);
    if(r.code == QAR_STATUS_RENDERING_PRODUCER_STREAM_IS_CLOSED)
        return POLL_CLOSED;
    if(qar_result_is_error(r) || !ready)
    {
        viewer->ready = NULL;   /* busy, paused, reconnecting, not set up yet */
        return POLL_NOT_NOW;
    }
    return POLL_FRAME;
}

for(;;)   /* your loop, at its own rate */
{
    update_viewers(&viewers);
    bool rendered = false;
    for(size_t i = 0; i < viewers.count;)
    {
        Viewer* viewer = &viewers.items[i];
        Poll poll = poll_frame(viewer);
        if(poll == POLL_CLOSED)
        {
            drop_viewer(&viewers, viewer);   /* swap-removes: item i is the next viewer */
            continue;
        }
        if(poll == POLL_FRAME)
        {
            render_views(viewer, viewer->ready);   /* only for a viewer that asked */
            show(viewer->sender);                  /* also when rendering failed */
            qar_render_frame_info_handle_destroy(viewer->ready);
            viewer->ready = NULL;
            poll_frame(viewer);                    /* arm the next wait now */
            rendered = true;
        }
        ++i;
    }
    if(!rendered)
        sleep_ms(1);   /* nobody needed a frame: do not spin (or wait for your frame tick) */
}
```

```csharp
sealed class Viewer : IDisposable
{
    public Viewer(RenderSender sender) { Sender = sender; }
    public RenderSender Sender { get; }
    public RenderFrameInfo? Ready;   // a frame begun and not yet rendered
    public void Dispose() { Ready?.Dispose(); Sender.Dispose(); }
}

enum Poll { Frame, NotNow, Closed }

// Never blocks. Poll.Frame leaves the frame in viewer.Ready.
static Poll PollFrame(Viewer viewer)
{
    if (viewer.Ready != null)
        return Poll.Frame;   // came back when the last show armed it
    Result<RenderFrameInfo?> polled = viewer.Sender.TryBeginFrame();
    if (polled.Info.StatusCode == StatusCode.RenderingProducerStreamIsClosed)
        return Poll.Closed;
    if (!polled.IsSuccess || polled.Value == null)
        return Poll.NotNow;  // busy, paused, reconnecting, not set up yet
    viewer.Ready = polled.Value;
    return Poll.Frame;
}

while (running)   // your loop, at its own rate
{
    UpdateViewers(viewers);
    bool rendered = false;
    foreach (var (id, viewer) in viewers.ToArray())
    {
        Poll poll = PollFrame(viewer);
        if (poll == Poll.Closed)
        {
            viewers.Remove(id);
            viewer.Dispose();
            continue;
        }
        if (poll != Poll.Frame)
            continue;
        using (RenderFrameInfo frame = viewer.Ready!)
        {
            viewer.Ready = null;
            RenderViews(viewer.Sender, frame);   // only for a viewer that asked
            viewer.Sender.ShowFrame().EnsureSuccess(); // also when rendering failed
        }
        PollFrame(viewer);                       // arm the next wait now
        rendered = true;
    }
    if (!rendered)
        Thread.Sleep(1);   // nobody needed a frame: do not spin (or wait for your frame tick)
}
```

`try_begin_owned_frame` refuses while a frame of the sender is open, so the frame an arming call returns is kept in `Viewer::ready` and rendered on the next pass.

```rust
enum Poll {
    Frame(OwnedFrame),
    NotNow,
    Closed,
}

/// Never blocks.
fn poll_frame(viewer: &mut Viewer) -> Poll {
    if let Some(frame) = viewer.ready.take() {
        return Poll::Frame(frame); // came back when the last show armed it
    }
    match viewer.sender.try_begin_owned_frame() {
        Ok(Some(frame)) => Poll::Frame(frame),
        Ok(None) => Poll::NotNow, // busy, paused
        Err(error) if error.has_code(StatusCode::RENDERING_STREAM_IS_CLOSED) => Poll::Closed,
        Err(_reconnecting_or_not_set_up_yet) => Poll::NotNow,
    }
}

fn request_driven_loop(
    session: &Session,
    peer_updates: &Receiver<PeerInfo>,
    running: &dyn Fn() -> bool,
) {
    let mut viewers: HashMap<PeerId, Viewer> = HashMap::new();
    while running() {
        // Your loop, at its own rate.
        update_viewers(session, &mut viewers, peer_updates);
        let mut rendered = false;
        viewers.retain(|_, viewer| {
            let mut frame = match poll_frame(viewer) {
                Poll::Frame(frame) => frame,
                Poll::NotNow => return true,
                Poll::Closed => return false, // drops the viewer's sender
            };
            // Only for a viewer that asked; shown also when rendering failed.
            let views = views_of(&frame);
            if let (Ok(views), Ok(mut textures)) = (views, frame.cpu_frame()) {
                render_views(&mut textures, &views);
            }
            let _ = frame.show(&ShowParams::default());
            // Arm the next wait now, so it runs while the loop is idle.
            if let Poll::Frame(next) = poll_frame(viewer) {
                viewer.ready = Some(next);
            }
            rendered = true;
            true
        });
        if !rendered {
            // Nobody needed a frame: do not spin (or wait for your frame tick).
            std::thread::sleep(Duration::from_millis(1));
        }
    }
}
```

- **Pros:** one thread and one renderer for every viewer; a slow, paused or reconnecting viewer holds back no other; frames are still rendered only when a viewer asked, and paced by the mixer.
- **Cons:** you keep a frame slot per viewer and must arm the next wait after each show.
- **Choose it** when one render loop serves several viewers and can render whenever a request is ready.

### Sequential or parallel sending

The loops above send **sequentially**: one thread visits every viewer. You can also send in **parallel**: a worker thread per viewer, each running the same per-viewer step on its own sender.

| | Sequential (one thread) | Parallel (a worker per viewer) |
|---|---|---|
| Renderer | One, shared; simplest | One per worker, or a renderer that takes work from several threads |
| A slow viewer | Holds back no other with a non-blocking loop; with a blocking one, every viewer | Holds back no other |
| Use it when | Rendering for a viewer is quick next to a display frame | Rendering for each viewer takes a large part of a display frame |

A sender is used from one thread at a time: keep each viewer's sender on its worker.

## Implementing the free-running mode

The [Vulkan cube example](https://github.com/Quaternar/qaros/tree/main/qar-streaming-c/examples/vulkan_cube) is the reference implementation in C++ on the C API: it runs this loop by default, on a fixed 60 fps schedule whose waits are the time left until the next slot, so a frame that runs long does not shift the ones after it.

Your loop renders on its own schedule and sends to whichever viewers are ready. Create the senders free-running ([Creating a sender in each mode](#creating-a-sender-in-each-mode)), serve them as a collection as in [Serving several viewers](#serving-several-viewers), and each pass, for each viewer:

1. `is_ready_for_next_frame` — never blocks. True once the viewer handed back the previous frame's destination; the destination is then reserved for this viewer's next frame. False while it is busy, paused or reconnecting: skip the viewer, render nothing for it.
2. `next_render_pose` — the poses for this frame, predicted for when it will be shown.
3. Render into your own target.
4. `begin_frame` — returns at once with the reserved destination and exactly the poses of step 2.
5. Copy your target into the frame and show it.

```c
for(;;)   /* your loop, at its own rate, or uncapped */
{
    update_viewers(&viewers);
    bool rendered = false;
    for(size_t i = 0; i < viewers.count;)
    {
        Viewer* viewer = &viewers.items[i];
        bool ready = false;
        QarResult r = qar_render_sender_is_ready_for_next_frame(viewer->sender, &ready);
        if(r.code == QAR_STATUS_RENDERING_PRODUCER_STREAM_IS_CLOSED)
        {
            drop_viewer(&viewers, viewer);   /* swap-removes: item i is the next viewer */
            continue;
        }
        ++i;
        if(qar_result_is_error(r) || !ready)
            continue;   /* busy, paused, reconnecting: no pose, no render, no copy */

        QarPose poses[2];
        QarFov fovs[2];
        if(qar_result_is_error(qar_render_sender_next_render_pose(viewer->sender, 2, poses, fovs)))
            continue;   /* no head pose yet, app volume unresolved: next pass */
        render_into_own_target(viewer, poses, fovs);

        QarRenderFrameInfo* info = NULL;
        if(qar_result_is_error(qar_render_sender_begin_frame(viewer->sender, NULL, &info)))
            continue;   /* the stream changed state since the check: next pass */
        copy_into_frame(viewer);   /* your target into the sender's textures */
        show(viewer->sender);
        qar_render_frame_info_handle_destroy(info);
        rendered = true;
    }
    if(!rendered)
        sleep_ms(1);   /* nobody was ready: do not spin (or wait for your frame tick) */
}
```

## Stream states

A viewer's stream is not always ready for a frame. Each loop below handles every state the same way:

| State | Non-blocking calls return | Blocking begin-frame | The loop |
|---|---|---|---|
| **Ready** | A frame (`try_begin_frame`), or ready (`is_ready_for_next_frame`) | Returns the frame | Renders and shows it |
| **Busy**: the viewer has not taken the previous frame yet | Not ready | Waits | Skips this viewer this pass |
| **Paused**: the viewer's display is not visible | Not ready, or `QAR_STATUS_MEDIA_STREAMING_STREAM_IS_PAUSED` | Waits until it resumes | Skips it and keeps the sender |
| **Reconnecting**: the connection dropped, auto-reconnect is on | Not ready, or `QAR_STATUS_MEDIA_STREAMING_STREAM_IS_RECONNECTING` | Fails with that code | Skips it and keeps the sender; it resumes by itself |
| **Not set up yet**: no head pose yet, app volume not resolved | `QAR_STATUS_RENDERING_PRODUCER_MISSING_POSE_DATA`, `QAR_STATUS_RENDERING_PRODUCER_APP_VOLUME_UNRESOLVED` | Fails with that code | Retries next pass |
| **Closed for good** | `QAR_STATUS_RENDERING_PRODUCER_STREAM_IS_CLOSED` | Fails with that code | Destroys the sender and removes the viewer; creates a new sender for it while the peer list still shows it online, after a back-off ([When a Target Restarts](/docs/developer-guide/restarting-targets)) |

- C# names the codes `StatusCode.MediaStreamingStreamIsPaused`, `MediaStreamingStreamIsReconnecting`, `RenderingProducerMissingPoseData`, `RenderingProducerAppVolumeUnresolved` and `RenderingProducerStreamIsClosed`; Rust `StatusCode::MEDIA_STREAMING_STREAM_IS_PAUSED`, `MEDIA_STREAMING_STREAM_IS_RECONNECTING`, `RENDERING_MISSING_POSE_DATA`, `RENDERING_APP_VOLUME_UNRESOLVED` and `RENDERING_STREAM_IS_CLOSED`.
- **Show every frame you began**, also when your rendering failed: until it is shown, the viewer's destination stays with you and the viewer shows the source as not responding. The API has no invalid marker; show what you have.

## Saving resources

Every loop above renders for a viewer only when that viewer needs a frame.

| Viewer | Request-driven, blocking | Request-driven, non-blocking | Free-running |
|---|---|---|---|
| Slow (busy with the last frame) | Its thread waits, renders nothing | Skipped, nothing rendered | Skipped by the readiness check, nothing rendered or copied |
| Paused | Its thread waits, renders nothing | Skipped | Skipped |
| Reconnecting | Begin fails, nothing rendered | Skipped | Skipped |
| Gone | Thread ends, sender destroyed | Sender destroyed | Sender destroyed |
| None connected | No threads | The pass finds nothing ready and sleeps | The pass finds nothing ready and sleeps |

- An **uncapped** free-running loop renders at most once per viewer frame: the readiness check is true only once the viewer handed back its last frame's destination.
- When nothing was ready in a pass, sleep briefly or wait for your own frame tick; polling in a tight loop burns a core for nothing.

## Which to choose

| | Request-driven, blocking | Request-driven, non-blocking | Free-running |
|---|---|---|---|
| Who sets the frame rate | The mixer, per viewer | The mixer, per viewer | Your loop, limited by each viewer |
| Threads | One per viewer | One | One, or a worker per viewer |
| Calls per frame | begin, show | try_begin, show, try_begin | is_ready, next_render_pose, begin, show |
| Rendered into | The sender's frame | The sender's frame | Your own target, then copied |
| A slow or paused viewer holds back others | Only if threads share a renderer | No | No |

1. **One viewer, or a thread per viewer is easy for you:** request-driven, blocking.
2. **One render loop for several viewers that can render when asked:** request-driven, non-blocking, with the next wait armed after each show.
3. **Your engine owns the frame loop and renders on its own schedule:** free-running, with the readiness check before every render.
